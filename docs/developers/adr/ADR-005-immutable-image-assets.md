# ADR-005: Immutable image sources, bounded decoding and shared display pyramids

**Status:** Accepted contract; implementation awaiting validation  
**Date:** 2026-10-01  
**Scope:** Milestone Required (MVP)

**Text/presentation extension:** [ADR-006](/developers/adr/ADR-006-shaped-text-and-canvas-preview) adds prepared shaped outlines and shared CPU canvas presentation. The pending statements below record this ADR’s original wave; current remaining scope/evidence is in the execution ledger.

## Context

Image placement swallowed file/codec errors, consumed IDs and created a default rectangle without a valid source. The raw importer checked decoded dimensions after decoding and truncated gray/gray-alpha 16-bit inputs to 8 bits. Canvas painting decoded compressed bytes or read the source path on every paint, ignored rotation/opacity and enlarged small images to a minimum of ten screen pixels. CPU export rejected all image objects. The histogram decoded the source repeatedly and had no 16-bit display path.

## Decision

`EncodedImage` is an immutable original with private bytes and a SHA-256 content key calculated once. `ShapeKind::Image.data` shares it with `Arc`; its native representation remains the existing byte array. Schema 3 is unchanged. Content keys identify cache entries, never document objects: `ObjectId` remains canonical identity. Source precision, profiles and metadata remain in the encoded original. Debug output contains only length/key. Bounded deserialization admits at most 32 MiB per encoded source; binary resource packaging, document-wide source accounting and COW containers remain M0 work.

The GUI-free raster crate owns common decoding. Quotas are conjunctive: mip preparation can reject a source that fits raw decoding. Source, cache, codec scratch, renderer intermediates and Skia upload budgets are separate; none is a whole-process RSS cap. PNG, JPEG, WebP and RGB/gray TIFF are admitted by magic. Defaults are 32 MiB encoded bytes, 32,768 pixels per axis, 16,777,216 pixels, 128 MiB normalized output, 512 MiB conservative decode/preparation working storage and 4 MiB extracted ICC profile. Codec limits are installed before decoding; checked dimensions/output/overlapping conversion sizes precede pixel decoding. Codec-private metadata allocations remain best effort, and the profile bound is checked after extraction; these limits are not a complete hostile-codec memory/time sandbox.

Decoded native samples use straight-alpha RGBA8 or RGBA16, preserving gray and gray-alpha 16-bit precision. Raw tile export explicitly unassociates premultiplied RGBA8/RGBA16 instead of darkening straight-alpha output. All 16-bit domain/raw storage is little-endian; the PNG encoder adapter converts to native endian where required. EXIF orientation changes decoded dimensions and display pixels while leaving the original bytes untouched. The low-level decoded resource retains ICC metadata; display preparation rejects tagged ICC sources before pixel decoding until a CMM is available. Four-component JPEG and CMYK TIFF cannot silently enter the library's RGB preview. HDR/float sources, animated PNG/WebP, declared non-sRGB PNG gamma/chromaticities without sRGB override and non-sRGB CICP receive an explicit missing-capability reason. Untagged RGB/gray and declared sRGB use the scoped MVP sRGB interpretation. Full ICC/CMYK remains V1 Required.

`ImageCache` has a default 128 MiB resident pixel/profile budget and 256 entries. Both CPU renderers and GUI adapters share the default cache; callers may supply an isolated cache. Warm access is by content key. A single active cold preparation deduplicates overlapping misses and bounds simultaneous codec/scratch work. LRU evicts only entries without external image owners; residency remains charged until the last owner drops. Pinned resources or too many pinned entries return a limit error. Invalid/unsupported sources have bounded negative-cache entries; cancellation and pressure-dependent limit errors are retryable. Cancellation is checked around decoding and between conversion/downsampling rows; a codec call or mutex wait cannot be interrupted mid-call.

Display/export derivatives are premultiplied encoded-sRGB RGBA8. Pyramids are built in linear-light premultiplied float scratch and then encoded per level. Exact area footprints include every source pixel when dimensions are odd. Transparent RGB cannot leak into downsampled edges. Conservative isotropic LOD uses the largest singular value of the source-to-device transform; sampling is bilinear within the selected level. This is not trilinear interpolation or EWA/anisotropic filtering. Rebuildable display quantization never replaces 16-bit source/editing storage. CPU scene preflight pins each prepared source through the render and fails explicitly when its cache budget cannot fit the scene.

Image coverage is the full placed local rectangle folded through live modifiers. Crop changes coverage without stretching the source; empty crops remain empty. CPU image pixels participate in ancestor transforms, isolated groups, fills/strokes, alpha/vector/luminance masks, spatial transparency, adjustments and available ordered effects. Perspective/contour image sampling still requires a separate adapter and returns a capability reason. Rendering never opens a source path: old path-only objects need explicit relinking.

Placement reads a regular file with bounded, fallible growth, then admits/prepares it before allocating an ID or submitting `CreateShapeObject`. Errors publish no object, selection, revision or history entry. File/Image menus, the palette and Assets panel open a localized path dialog with visible failures; success retains exact source bytes and makes one reversible command. Native file chooser/portal integration is still pending. The Skia adapter uses the same cache and a separate thread-local LRU capped at 64 MiB of pixel uploads/128 entries; it applies world transforms, opacity and bilinear sampling. Its histogram is an approximate sampled RGBA8 display histogram, not a full-precision statistical analyzer. Cold import/GUI cache misses are still synchronous; worker-driven UI preparation/presentation and complete scene parity remain M1 work.

## Consequences and evidence

This closes a source/import/CPU-image implementation gap, not M0, M1 or the MVP. Regression sources cover identity/wire preservation, reuse/concurrency, negative caching, LRU/pinned budgets, cancellation, alpha/linear-light/odd-size mips, 16-bit gray, ICC admission, JPEG component/orientation rules, placement atomicity, undo/redo, native round trips, missing original paths, CPU crop/group/mask/transparency and explicit capability failures. No tests, builds, Clippy, corpus comparisons, documentation gates or Linux/product checks were run for this continuation: the user deferred validation until all MVP features are implemented. Historical foundation results do not validate this implementation.

Algorithm references: Lance Williams, *Pyramidal parametrics* ([1983 DOI](https://doi.org/10.1145/800059.801126)); Porter and Duff, *Compositing digital images* ([1984 DOI](https://doi.org/10.1145/800031.808606)). Crossref records were consulted for titles/authors/DOIs, not complete paper readings. Locally installed `image` 0.25.10, `tiny-skia` 0.11.4 and Skia adapter sources informed API/precision/limit behavior. The open [PBRT v4 mipmap implementation](https://github.com/mmp/pbrt-v4/blob/master/src/pbrt/util/mipmap.cpp) was inspected for pyramid accounting and EWA footprint differences; this implementation does not claim PBRT's filtering quality or competing-application equivalence. The academic references are rationale, not acceptance results.
