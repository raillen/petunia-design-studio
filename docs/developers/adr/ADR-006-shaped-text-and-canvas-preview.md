# ADR-006: Shaped text outlines and latest-request canvas presentation

**Status:** Accepted contract; implementation awaiting validation  
**Date:** 2026-10-01  
**Scope:** Milestone Required (MVP)

## Context

The desktop painted a flat list with independent Skia approximations. This lost group composition, masks and shared effects, and cold image preparation still ran during painting. Text used one default-font `draw_str`, without the document's actual family, multiline flow or shaping. The CPU scene rejected text. Revision alone cannot identify a preview: two tabs can have the same revision and surface ID, and a camera/channel change can leave a result obsolete without any document edit. Continuous viewport work also exposed linear job lookup and unbounded completed-job history.

## Decision

The GUI-free text crate uses the existing process-wide Cosmic Text 0.19 font system, advanced shaping and width-constrained `WordOrGlyph` layout. Tracking in document points is converted to EM. UTF-8 source clusters, resolved font families, glyph advances and bidi direction travel with immutable prepared metadata. The same `LineIter` paragraph offsets as the buffer preserve CR/LF/CRLF/LFCR source ranges. Unhinted TTF/CFF outlines are extracted with ttf-parser 0.25.1, scaled from font units, flipped into the downward-positive document frame and positioned using shaped offsets/baselines. Font database IDs remain cache handles, never canonical/persisted document IDs.

Original `ShapeKind::Text` stays editable. `RenderGeometry` retains the prepared owner, so cached outlines cannot outlive their charged residency through an exposed path Arc. Live modifiers derive a separate evaluated path; they do not replace the original text. Exact signed Bézier area and whole-contour reversal normalize opposite TTF/CFF winding without flattening or changing counters. Text uses nonzero winding for fills, aligned strokes and vector clips; existing vector shapes retain even-odd coverage. Bounds come from actual ink; empty/whitespace text does not invent a rectangle. Visible text participates in ancestor transforms, isolated groups, masks, available fills/strokes, transparency, adjustments and ordered effects through the CPU renderer used by PNG export. Hidden text and descendants of hidden containers do not prepare unsupported glyphs. Scene extraction checks cancellation between nodes/glyphs.

Prepared text has a 64 MiB retained derivative budget, 128 entries, 64 KiB source text, 1,024 family bytes, 65,536 glyphs and one million combined/scratch outline verbs per flow. Admission counts path/glyph capacities, stored family strings and key bytes. A serialized cold path prevents duplicate preparation; LRU evicts only unpinned owners. This is not a whole-process RSS or shaping-time sandbox: system-font discovery, the font database/private shaping allocations, modifier-derived scene paths and toolkit allocations have separate or incomplete accounting. Cancellation cannot interrupt a font/shaping call or mutex wait mid-call. Cache identity includes content, family and every supported layout metric. The current scene uses uniform family/size/line-height/tracking, full width-wrapped flow without implicit height clipping, and no rich styles, variable coordinates, vertical text or typographic overflow mode. Uncovered glyphs, visible text-on-path and variable/color/bitmap/SVG glyph adapters fail with a capability reason.

`PreviewSource` captures immutable canonical surface descriptors once per revision. Paths and encoded image originals retain their shared buffers; document containers/text strings are still copied on capture. A typed process-local source ID prevents cross-session collisions. Shell selection/camera updates reuse the source; session replacement clears it. Workers extract/cache the shared scene and prepare/render images and text. The GUI performs nonblocking polling and one Skia upload per completed frame, retaining one upload rather than the removed per-image painting cache. Pointer gestures, rulers, guides and selection remain GUI overlays.

`PreviewController` owns two workers, a queue of two, one desired request and one visible complete frame. Replacement cancels the previous handle. Publication checks the complete source/revision/viewport/dimension/channel/proof request, not only revision. A previous camera frame may remain visible only for the same source and display mode, projected at its original world region while the replacement runs. A changed source/channel/proof immediately suppresses it, including at the GUI boundary before asynchronous polling resumes. Temporary queue pressure retries the latest request; deterministic failures stop until the request changes. Owner teardown cancels work and executor drop does not join on the UI thread.

The CPU preview composes root blend modes against the existing neutral gray artboard with transparent pasteboard; PNG export retains its caller-selected backdrop. This establishes a common compositor, not identical outputs with different backdrops or complete product color management. Channel isolation happens after full composition. ICC soft proof returns an unavailable-CMM reason instead of applying the old artwork heuristic. The canvas displays a localized failure prefix. Output admission is 16,777,216 pixels (at most 64 MiB RGBA8/backdrop/upload each); renderer intermediates, image cache, text cache, in-flight workers and toolkit copies are separate budgets. Upload still copies a completed frame on the UI thread; tiled presentation and measured latency/RSS remain open.

Job records use indexed lookup, bounded UTF-8 labels and at most 256 terminal records, keeping active queued/running records. Terminal state cannot be rewritten; token cancellation wins completion/failure. Canceled queued work releases its admission slot before a worker becomes available. This bounds executor-owned queued work/history, not arbitrary callers repeatedly creating unfinished legacy metadata jobs.

## Consequences and evidence

This advances M1/M2; it does not complete them or the MVP. Remaining work includes text editing/caret/grapheme/IME and styles, text-on-path, coherent text hit-testing/overflow, font diagnostics and reproducibility/licensing, total document/scene budgets, tiled workers, persistent bitmap layers/masks, resource packaging/COW/recovery and the original Linux/product acceptance gates. ICC/CMYK/professional PDF remain V1 Required.

Regression sources cover cache sharing, real glyph ink/counters, ligatures, UTF-8/bidi and newline ranges, tracking/wrapping, empty text, cancellation/admission, rotated isolated text, crop/blur/vector masks, hidden/attached capability cases, complete preview keys across tabs/cameras/channels, replacement pressure, common-backdrop CPU parity and bounded job history. **None has been executed for this continuation.** The user deferred builds, tests, lint/conformance/migration/docs gates until all MVP features are implemented; historical foundation results do not validate this head.

References inspected: locally installed Cosmic Text buffer/layout/font/paragraph implementations, fontdb face-data access, ttf-parser outlines and Freya reactive futures/state/Skia upload APIs. Relevant sections of [Unicode UAX #9](https://www.unicode.org/reports/tr9/) distinguish logical source order from per-line visual reordering; [UAX #29](https://www.unicode.org/reports/tr29/) distinguishes grapheme editing from shaped glyph clusters. These inform the contract without claiming a new complete Unicode editor or independent conformance. The compositor's academic rationale remains Porter–Duff, *Compositing digital images*, as recorded in [ADR-005](/developers/adr/ADR-005-immutable-image-assets); no new full-paper review or competitor-equivalence evidence is claimed.
