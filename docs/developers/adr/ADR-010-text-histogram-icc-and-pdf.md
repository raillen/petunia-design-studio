# ADR-010: Draft text, composition histograms, ICC resources and faithful PDF

**Status:** Accepted implementation contract; final verification recorded separately.
**Date:** 2026-10-03
**Scope:** Milestone Required (MVP corrections); V1 Required (bounded color/PDF foundation).

Native raster/resource/interchange statements below describe the ADR-010 baseline and are superseded by [ADR-011](/developers/adr/ADR-011-native-cmyk-raster). Native process proof and professional print release acceptance remain open.

## Context

The earlier MVP continuations were merged without executing their deferred tests. Text editing did not share artwork caret geometry, histograms could synthesize statistics, named press profiles did not establish an ICC conversion, and PDF export could substitute geometry or omit document semantics. A connected handler is not evidence that a product task or professional print workflow is complete.

## Decision

1. `TextEditBuffer` uses UTF-8 grapheme boundaries, selection, bounded local undo and transient IME preedit. The canvas derives selection/caret geometry from the same prepared glyph clusters and font faces used for rendering. Draft content is materialized on a worker through `DocumentMutator`; committing sends one guarded object command. Escape discards drafts, tab/session identity prevents cross-document writes, and clipboard completions require the original selection/content. Native multiline accessibility enables compositor IME; physical Linux IME and assistive technology acceptance remain separate gates. Ligature carets divide advances; GDEF caret positions and full rich text navigation remain V1 Required.
2. Histograms analyze the rendered visible composite, including masks, ancestor transforms, pixel layers and supported adjustments. Selecting an object scopes analysis to its visual bounds, not an isolated layer. Bins use straight encoded sRGB channels/Rec.709 luma, alpha weights and at most a 512-pixel longest edge. Empty/transparent input reports zero statistics. A bounded worker cancels superseded work and publishes only the current source identity; canvas, text/raster drafts and analysis share prepared scenes. This is a display histogram, not full-resolution linear sensor statistics.
3. Validated ICC v2/v4 bytes are immutable, SHA-256 addressed, at most 4 MiB per profile and included in document admission budgets. A surface may assign a CMYK output profile through a reversible command. Schema 5 stores these bytes as resources in index v2; schemas 1–4 remain readable and index v1 carries no profiles. Metadata never embeds profile arrays in the binary package. Corruption, unbound profiles and malformed ranges fail admission.
4. LittleCMS converts typed unit CMYK channels using its percentage convention, and RGB uses unit channels. CMYK-to-CMYK conversion has no RGB intermediate; the same profile preserves all authored inks. Monitor/output profiles, all four intents and BPC are explicit proof inputs. Proof transforms the derived **sRGB composition** through the loaded press profile to the chosen RGB monitor, preserving alpha; it does not write artwork back. Process vector paints use the assigned profile for display and SVG. Name-only SWOP/FOGRA simulations, invented gamut diagnoses and fixed preservation factors are removed. The test profile is a project-owned synthetic LUT, not a certified press reference.
5. PDF consumes the immutable render scene and exact shaped font resources. Supported output preserves page origins/dimensions, bleed/trim/crop boxes, group transforms/isolation/blends, multiple fills/strokes, gradient stops, vector/alpha clips, images, pixel layers and embedded shaped text. Scoped graphics state is balanced even when a nested operation fails. Strict mode rejects unsupported or approximate semantics. Explicit degradation may rasterize an entire supported effect page using the CPU renderer at the selected DPI and records that loss. Unknown colors are reported; no geometry is invented. Export observes cancellation before returning bytes.
6. `AppearanceStack::default()` is opaque, token RGBA alpha is applied once, and artboard preview uses the canonical background. History coalesces repeated property changes within a structural epoch, preserving the first before-state and final after-state. Delete/recreate/reparent barriers preserve replay dependencies; return-to-origin gestures retain redo. Binary history budgets avoid serializing tile/profile payloads just to count them.
7. CI installs the native build dependencies. `ui-gauntlet` executes actual Freya tests; fuzz/release stubs and missing documentation dependencies cannot report success. Generated source references and the final execution ledger are committed with the implementation.

## Consequences and verification

Focused regressions cover Unicode/IME, glyph-derived carets, immutable drafts, long gestures/redo/barriers, histogram occlusion/stale work, ICC admission/native units/alpha/cancellation, schema migration/resource digests, and PDF interoperability. Poppler independently parses pages, extracts embedded text and renders PDF pixels for comparison with the CPU scene. Full workspace formatting, Clippy, tests, architecture, conformance, fixtures and bilingual documentation gates run only after the implementation phase, as requested.

These automated checks are bounded evidence. They do not certify tablet pressure, accessibility, display calibration, installations, long sessions or human acceptance of the four MVP task projects. **MVP release acceptance remains open. V1 is not complete:** RGBA/Gray tiles do not provide four native CMYK planes; separations/TAC/DeviceLink black preservation, overprint, spot workflow parity, float process colors, full typography/shaped text on paths, PDF/X-4 OutputIntent/conformance and independent print validation remain V1 Required. Capabilities `ptnd.raster.cmyk` and `ptnd.export.pdf-x4` stay disabled with reasons.
