# 00.2 — Product Principles, UX Values & Accessibility Commitments

# Principles

1. Editability before destructive convenience.
2. Explicit state before hidden magic.
3. One semantic model across GUI, plugin and MCP.
4. Precision without forcing complexity.
5. Progressive disclosure rather than separate beginner/pro app.
6. Recoverability and undo as product features.
7. Accessibility built into components/tools.
8. Local-first and privacy-conscious.
9. Interoperability described honestly with fidelity grades.
10. Performance is part of interaction design.

# Neurodivergent-friendly design

Stable panel placement, command search, predictable context groups, reduced visual noise, strong focus indication, customizable density, optional reduced motion, clear destructive/live distinctions and search/filter in large panels.

# Error philosophy

Explain what failed, why, what was preserved and the safest recovery. Avoid modal interruption unless user decision is required.

# Discoverability

Every icon-only action has tooltip/accessible label. Important actions exist in command palette/search. Disabled actions can explain why.

# Consistency

Same property/action must look and behave similarly across Personas and tools unless domain semantics justify divergence.
