# Dossiê V1 — Implementado × Desejado + Guia de Implementação (2026-09-30)

- **Branch:** `work/f6-f7` (base `main` em `217bfcd`: Freya shell + paridade Ciclos 1–5 + perf F1–F5 sobre batches 1–14)
- **Stack:** Rust + Freya `0.5.0-rc.7` (Skia). Slint congelado como referência histórica.
- **Propósito:** guia das conversas e da implementação, assunto a assunto, granular e incremental — cada linha abaixo vira um ciclo fechado (hipótese → teste que falha antes → implementação → prova).
- **Regra de honestidade:** status só com fonte. `PROVEN` exige teste nomeado. Spec sem código é `N` (não revalidada aqui).

## 0. Enquadramento: o problema real

O núcleo V1 está **sinteticamente aprovado** (suítes verdes: 121 testes de tools, 9 de compositor, app, documento) mas **falso na usabilidade real**: ferramentas quebradas no uso, performance terrível em cena densa. Testes headless provam contrato, não experiência. Por isso cada item deste dossiê fecha com **prova de uso real** (gesto no canvas a 60fps), não só teste verde. Doutrina-mãe: `TOOLS_DECISIONS.md` (1 gesto = 1 undo, conversão só no gesto que exige, Bake explícito).

## 1. Legenda

Status: **PROVEN** (teste nomeado) · **PARCIAL** (funciona com lacuna exata) · **AUSENTE** · **DISABLED** (registry com motivo) · **DÍVIDA** (spec × código divergem) · **DECLARADO** (doc alega, não revalidado aqui).
Prioridade: **P0** caminho crítico · **P1** V1_REQUIRED · **P2** polish/Milestone · **P3** Post-V1.
Tamanho: **XS** horas · **S** 1 batch · **M** 2–3 · **L** epic · **XL** multi-epic.
Fonte: **C** código+teste · **T** TOOLS_DECISIONS · **M** TOOLS_MAP · **S** surfaces registry (134 entries) · **P** PERF/GAUNTLET · **L** ledger M1–M20 · **D** PENDING · **N** spec normativa 08/09/10/15.
